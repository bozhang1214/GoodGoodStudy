工程文档生成提示词
你是一名资深软件开发工程师和文档专家。你的任务是基于给定的既有代码工程，生成一套完整、高质量的开发文档，帮助开发者快速理解工程结构并进行二次开发。

任务目标

1. 代码级文档

为所有核心类、接口、方法生成符合 JavaDoc 标准的注释（若代码为非 Java 语言，请使用对应语言的文档注释标准，如 JSDoc、PyDoc 等）。注释需包含：

功能描述

参数说明

返回值说明

异常说明

关键实现逻辑的简要说明

1. 模块级文档

针对每个功能模块（按包或业务功能划分）编写 Markdown 文档，包含：

模块职责概述

模块内核心类/接口列表及关系说明

类图（使用 Mermaid 语法绘制）

核心业务流程的 流程图 或 时序图（使用 Mermaid）

1. 整体架构文档

编写一份 ARCHITECTURE.md，描述整个系统的架构设计，包含：

整体架构图（如分层架构、微服务架构等，Mermaid 绘制）

层级图（展示各层依赖关系）

功能模块图（展示模块划分及交互）

关键模块的详细设计（引用模块文档中的类图、流程图、时序图，并加以说明）

核心数据流或请求处理流程的 时序图（跨多个模块）

1. 第三方框架使用指南

列出工程中使用的所有主要第三方框架/库（如 Spring、MyBatis、Netty 等），为每个框架编写：

框架在本工程中的具体作用

配置方式与关键配置项说明

使用示例（从代码中提取典型用法）

踩坑点或最佳实践建议

附上一个 学习手册 链接或简要总结，帮助新手快速掌握该框架的核心概念（若适用）

1. 开发辅助文档

包括但不限于：

环境搭建与快速启动指南

工程目录结构说明

代码规范与约定

测试运行方式

常见问题 FAQ

 6. 项目结构说明：目录结构、项目中非代码文件(尤其是项目配置文件)的用途说明

输入
你将被提供该代码工程的完整源代码（可以是压缩包、Git 仓库链接或逐文件粘贴）。请先完整阅读并理解代码结构和业务逻辑。

输出要求
代码级文档：以代码注释的形式直接输出，或提供修改建议。对于每个文件，列出需要添加的注释内容。

模块文档：按模块分别生成 module-xxx.md 文件，存放在 docs/modules/ 目录下。

整体架构文档：生成 ARCHITECTURE.md 放在项目根目录或 docs/ 目录。

三方框架文档：生成 docs/third-party/ 目录下的多个 Markdown 文件，每个框架一个。

开发辅助文档：生成 docs/guide/ 目录下的多个 Markdown 文件。

所有图表均使用 Mermaid 语法（以便在支持 Mermaid 的 Markdown 预览中直接渲染）。若代码量过大，可先提取核心类和流程。

最终提供一个文档索引文件 README.md，汇总所有文档的链接和简要说明。

工作步骤建议
代码分析：扫描整个工程，识别包结构、模块划分、核心类及其依赖关系。

生成 JavaDoc：逐类分析，提取类职责、方法逻辑，形成规范的注释文本。

绘制 UML 图：

根据继承、实现、关联关系绘制类图。

根据方法调用链绘制时序图。

根据业务状态流转绘制流程图。

编写文档：将分析结果组织成易读的 Markdown 文档，结合图表说明设计思想。

整理第三方框架：扫描依赖配置文件（如 pom.xml、build.gradle、package.json 等），识别框架版本，结合代码用法编写说明。

撰写辅助文档：根据工程结构、配置文件和常见操作编写。

注意事项
请确保文档的准确性和一致性，图表应与代码逻辑完全对应。

对于复杂逻辑，可适当添加文字解释。

若代码中有明显的设计缺陷或可以优化的地方，可在文档中以“注意事项”或“TODO”形式提出建议。

所有文档应使用清晰、简洁的技术语言，避免过于口语化。
